# TajStudio — отмена рендера, статус, готовые персонажи и сцены (ZIP)

## Mini App
- **Проекты → «Отменить рендер»**: останавливает Blender, готовые кадры остаются на сервере рендера (хранятся 24 часа).
- **Живой статус**: этапы «Озвучка → Сцена → Кадры → Склейка → Сохранение», текст «что сейчас», кадры «N / M», прошедшее и оставшееся время, последние строки лога Blender.
- **Ошибка или отмена → «Продолжить с N%»**: рендер идёт дальше с того кадра, где остановился (озвучка тоже не повторяется). Если сервер рендера уже удалил кадры — рендерится заново, но озвучка берётся из кэша.
- **Персонажи → «+» → ZIP**: бот сам определяет, что в архиве:
  - части куклы (`head.png`, `torso.png`, `arm_left.png`, … `mouth_*.png`, `eye_closed_*.png`, как в `EHSON_full.zip`) — будет плоский персонаж, рот и моргание меняются по озвучке;
  - Blender-скрипт сцены (`Build_*.py`, как в `Disney_Style_City_Street_...zip`) — вкладка «Сцены».
- **Сцены в сценарии**: `[Сцена: Улица]` или `@Улица`, если имя совпадает с загруженной сценой. Герои встают в сцену, камера выбирается так, чтобы не упираться в стены.

## Бот в чате
Пришли ZIP файлом — бот распакует, спросит имя. Во время рендера есть кнопка «⏹ Остановить», после остановки или ошибки — «🔁 Продолжить».

## Сервер рендера (VPS)
Новые методы: `POST /cancel/<id>`, `POST /resume/<id>`; `GET /status/<id>` теперь отдаёт `stage, done, frames, eta, tail, resumable`.
**Пересоберите Docker-образ** (`docker compose up -d --build`): в него добавлены `bl_cutout.py`, `bl_custom.py`, `scene_guard.py`, `cutout_layout.py`.

## Безопасность загружаемых сцен
Скрипт сцены проверяется (`scene_guard.py`): разрешены только безопасные импорты, убраны удаление чужих объектов, сохранение и запуск рендера. Это не полная песочница — загружайте только свои архивы; рендер при этом идёт внутри контейнера на VPS.

## Важно
Код Blender для кукол и сцен в этой среде не запускался (Blender тут нет) — проверен на заглушке и с настоящим ffmpeg. Сделайте короткий предпросмотр и пришлите ошибку, если будет.

# TajStudio — что нового (качество мультфильма + 3D-герои без загрузки)

**Загружать персонажа больше не нужно.** Если имени из сценария нет в «Мои персонажи», Blender сам «рисует»
3D-героя по сценарию: пол, возраст, животное (кот, собака, заяц, медведь, лиса, волк, мышь, свинья, лев, лягушка),
профессия (доктор, повар, король, волшебник, пират, космонавт…), цвета, причёска, одежда. Загруженные 2D-листы
по-прежнему работают и могут стоять в одной сцене с 3D-героями.

Формат сценария (всё, кроме реплик, необязательно):
```
[Персонаж: Маша — девочка 8 лет, рыжие косички, красное платье]
[Персонаж: Барсик — рыжий кот]
[Сцена: лес, утро]
Рассказчик: Однажды в лесу.
Маша: (радостно, машет рукой) Привет, Барсик!
Барсик: Мяу! Ничего себе, как тут красиво!
```
* `[Сцена: …]` — место (лес, дом, кухня, школа, город, пляж, космос, пустыня, горы, снег, деревня, ферма, парк, замок, офис),
  время суток (утро/день/вечер/ночь) и погода (снег) определяются по словам.
* В скобках — эмоция и действие: радостно, грустно, зло, удивлённо, испуганно, смеётся; машет, кивает, показывает, прыгает, танцует, кланяется.
  Без скобок эмоцию бот угадывает по тексту и знакам препинания.
* `Рассказчик:` — закадровый голос, камера показывает общий план.
* Герои получают разные голоса по полу (если голос не выбран вручную).

Что стало лучше в самом рендере: 3D-декорации и свет по времени суток; кино-камера (общий/средний/крупный план, наезд);
взгляд героев друг на друга, моргание, брови, жесты, выход в кадр; липсинк по громкости; исправлено наложение
сцен друг на друга; исправлена тихая озвучка при многих репликах (микс без деления громкости); тихая фоновая музыка,
нормализация громкости, плавное появление/затухание.

Новые файлы: `scenario.py`, `bl_common.py`, `bl_chars.py`, `bl_anim.py`, `bl_sets.py`, `bl_sprite.py` (рядом с `blender_worker.py`).
**На VPS пересоберите образ** (`docker compose build && docker compose up -d` в папке `vps/`) — Dockerfile копирует новые файлы.

Скорость рендера (на VPS без GPU): по умолчанию 1280×720, каждый 2-й кадр (на двойках), 24 сэмпла.
Настраивается в `vps/.env`: `RENDER_W`, `RENDER_H`, `RENDER_SAMPLES`, `RENDER_ENGINE` (`eevee`/`cycles`), `RENDER_MUSIC=0` (без музыки).
Если рендер идёт слишком долго — сначала смотрите «Предпросмотр» (640×360, каждый 3-й кадр), а для финала уменьшите `RENDER_SAMPLES`/разрешение.

# TajStudio — что изменилось

Файлы: `bot.py`, `tts.py` (новый), `prepare_character.py`, `index.html`, `requirements.txt`.
`blender_worker.py` и `split_sheet.py` без изменений. Замените файлы в репозитории целиком.

## Переменные окружения (Bothost)
| Переменная | Зачем |
|---|---|
| `BOT_TOKEN`, `FIREBASE_CRED_JSON`, `FIREBASE_DB_URL` | как раньше |
| `MINIAPP_URL` | адрес вашего бота на Bothost (`https://…`), **не GitHub Pages** — оттуда Mini App берёт API |
| `ELEVENLABS_API_KEY` | нужен только для озвучки ElevenLabs |
| `ELEVEN_DEFAULT_VOICE` | необязательно: id голоса ElevenLabs по умолчанию. Если пусто — берётся первый голос аккаунта |
| `PIPER_DEFAULT_VOICE` | необязательно, по умолчанию `ru_RU-irina-medium` |
| `MAX_RENDERS` | сколько рендеров одновременно (по умолчанию 1) |
| `YADISK_TOKEN`, `ADMIN_IDS`, `BLENDER_BIN` | как раньше |

`ELEVEN_VOICES` (старый формат `{"Маша":"voice_id"}`) всё ещё работает.

## Piper
* Ставится из `requirements.txt` (`piper-tts`).
* Голоса качаются сами с huggingface при первом выборе/использовании (около 60 МБ каждый) в папку `voices/`.
* Если хостинг не пускает на huggingface: скачайте `NAME.onnx` и `NAME.onnx.json` вручную, положите в `voices/` — голос появится в списке.
* Голоса в списке: Ирина, Дмитрий, Денис, Руслан (русские), Lessac, Amy, Ryan (английские). Список — `PIPER_CATALOG` в `tts.py`.
* Таджикского голоса в Piper нет.

## Не реализовано
* Музыка и звуковые эффекты — убраны из Mini App (в рендере их не было).
* Баланс/оплата — списания в боте нет; в интерфейсе скрыто (`CONFIG.BILLING` в `index.html`).

## Рендер на отдельном VPS (instabox.sh)
Бот остаётся на Bothost. Если в Bothost задать `RENDER_URL` и `RENDER_TOKEN`, Blender запускается не на Bothost, а на VPS (папка `vps/`). Без `RENDER_URL` всё работает как раньше.
| Переменная (Bothost) | Значение |
|---|---|
| `RENDER_URL` | `https://ВАШ-ДОМЕН-VPS` (без слэша в конце) |
| `RENDER_TOKEN` | тот же секрет, что в `vps/.env` на сервере |
